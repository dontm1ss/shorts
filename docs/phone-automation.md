# Автоматизация с телефона (прогрев и публикация)

Модуль `src/phone/` управляет физическим телефоном (Android 13, Galaxy A51), подключённым
по USB к прод-ПК, через `adb` + `uiautomator2`. Нужен для двух вещей, которые официальный
API TikTok закрывает без аудита приложения:

- **прогрев** аккаунта — «человеческие» сессии просмотра ленты;
- **публикация публично** — через API TikTok ролик уходит только в черновики
  (`upload.tiktok`, режим `inbox`), а с телефона можно постить публично, с полной подписью.

План и статусы — в `TODO.md`. Схема на текущий момент: **1 телефон = 1 аккаунт TikTok +
1 канал YouTube Shorts + 1 аккаунт Instagram Reels**; гео — ру-сегмент (страну прокси
выберем отдельно).

## 1. Подготовка телефона

1. **Включить режим разработчика**: Настройки → О телефоне → Сведения о ПО → нажать
   «Номер сборки» 7 раз (A51: обычно `Настройки → Об устройстве → Сведения о программе`).
2. **Настройки → Для разработчиков → Отладка по USB** — включить.
3. Samsung-нюанс: если на A51 есть «**Автоблокировка**» (`Настройки → Биометрия и безопасность →
   Автоблокировка`), отключить её — она блокирует ADB и установку неизвестных приложений,
   а uiautomator2 ставит на телефон свой агент.
4. Подключить кабель к прод-ПК; на экране телефона разрешить отладку с этого ПК (галочка
   «Всегда разрешать»).

## 2. Тулинг на прод-ПК

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup_phone.ps1
```

Ставит в `tools/` (в git не попадает): Google `platform-tools` (adb) и `scrcpy`
(зеркалирование экрана — удобно смотреть, что делает автоматизация). Плюс в venv —
`uiautomator2`. Проверка:

```powershell
venv\Scripts\python -m phone devices
tools\scrcpy\scrcpy.exe              # окно с экраном телефона
```

## 3. Прогрев и аккаунты

Перед тем как новый аккаунт начинает постить, его «прогревают»: обычные сессии просмотра
ленты со случайными паузами, изредка лайки. Прогрев идёт по площадкам
(`phone.warmup.platforms`: tiktok, youtube, instagram) и по тематике проекта: в части сессий
открывается поиск по ключевику (`phone.warmup.keywords` — «истории», «переписки», «нарезки»),
чтобы алгоритм подбирал похожую аудиторию.

```powershell
venv\Scripts\python -m phone warmup --platform tiktok --seed 1
venv\Scripts\python -m phone accounts          # статусы аккаунтов и прогресс
```

Что делает сессия: запускает приложение, при удаче ищет контент по ключевику (иначе — лента),
листает, смотрит ролики случайное время (`watch_min_s`…`watch_max_s`), с вероятностью
`like_probability` ставит лайк. Подписки и комментарии по умолчанию выключены. План строится
детерминированно от `seed` — проверяется без телефона (`warmup.build_plan`).

**Статусы аккаунта** (`data/phone-accounts.json`, `phone.accounts`):

| Статус | Значение |
|---|---|
| `new` | создан, прогрева ещё не было |
| `warming` | идёт прогрев (набирает `sessions_to_warm` сессий или `seconds_to_warm` секунд) |
| `warmed` | прогрет, можно публиковать |
| `active` | уже публикует ролики |
| `paused` / `banned` | пауза / бан (выставляется вручную) |

Переходы автоматические (первая сессия → `warming`, порог → `warmed`, первая публикация →
`active`); вручную статус меняется в панели (вкладка «Аккаунты») или в боте.

## 4. Публикация ролика

Из командной строки:

```powershell
venv\Scripts\python -m phone post <scene_id> --to tiktok
venv\Scripts\python -m phone post <scene_id> --to youtube
venv\Scripts\python -m phone post <scene_id> --to instagram --caption "свой текст"
```

Из панели и бота: у каждого готового ролика есть кнопки **«📱 TikTok / YouTube / Instagram»** —
публикация через приложение на телефоне задачей очереди (отдельная «телефонная» линия,
не мешает озвучке и рендеру). Тексты берутся из `publish_meta`, хэштеги добавляются
автоматически; после публикации аккаунт становится `active`, а ролик помечается отправленным.

Как устроено: ролик из манифеста (`output/videos/`) кладётся на телефон в
`phone.remote_dir` (`/sdcard/Movies/ShortsFarm`), приложение открывается, uiautomator2
проходит поток кнопок по шагам из `src/phone/selectors.py` и вписывает подпись.

### Настройка селекторов

Интерфейсы приложений меняются между версиями и регионами, поэтому селекторы — это
**отправные точки**, а не гарантия. Если шаг не находится, модуль делает снимок экрана в
`output/phone/<platform>_<step>.png` и пишет, какой шаг не прошёл. Порядок действий:

1. `venv\Scripts\python -m weditor` — графический инспектор элементов (ставится
   `pip install weditor`); навести на кнопку и посмотреть её текст/`resource-id`.
2. Поправить нужный шаг в `src/phone/selectors.py` (можно добавить вариант `text`,
   `resource_id`, `xpath` или `coord` — координатный тап как запасной).
3. Повторить `python -m phone post …`.

## 5. Прокси / VPN (как выйти в нужную гео)

Для ру-сегмента TikTok нужен выход не из России (ТикТок РФ с 2022-го не даёт постить).
Инструкция: `venv\Scripts\python -m phone proxy`.

Варианты на Android без root:

1. **Мобильный прокси нужной страны** (предпочтительно). IP настоящего мобильного оператора —
   самый «чистый» для площадки. По одному на аккаунт, липкий (sticky), чтобы гео не скакала.
   На телефоне — клиент провайдера (обычно v2rayNG/Clash или их фирменное приложение).
2. **Личный VPN на арендованном VPS** (запасной, дешевле): WireGuard или Outline.
   Конфиг WireGuard собирает `phone.proxy.wireguard_conf(...)`, на телефон ставится
   приложение WireGuard и импортируется `.conf`.

Проверка гео: в браузере телефона открыть `https://ipinfo.io` — страна должна быть нужной
и **не меняться** между сессиями.

## 6. Честно про баны

Прокси **недостаточно**, чтобы «не банило». Площадки (TikTok в первую очередь) складывают
множество сигналов, и IP — только один из них:

- **Качество IP.** Датацентр-IP (обычный арендованный VPS/VPN) — уже «мусорный» пул, с него
  сидели тысячи аккаунтов. Новый аккаунт на датацентр-IP в Тир-1 регионе — флаг сразу.
- **Один IP на несколько аккаунтов.** Общий VPN связывает аккаунты между собой → бан пачкой.
  Отсюда правило «1 телефон = 1 аккаунт = 1 IP».
- **Следы автоматизации.** uiautomator2 работает через accessibility-сервис; это не «невидимо»,
  хотя реальный телефон + реальное приложение намного безопаснее эмуляторов. Root на телефоне
  (например, Magisk на A51) повышает риск обнаружения, а не снижает — без необходимости не делать.
- **Поведение.** Резкие всплески, одинаковые действия, посты без прогрева, массовые одинаковые
  тексты — всё это детектится.

Рабочая цепочка: **отдельный мобильный/резидентный IP на аккаунт + реальное устройство +
постепенный «человеческий» прогрев + уникальный контент**. Тогда прокси — необходимое звено,
но бан-риск определяется всей суммой, а не только им.
