# ТЗ: Платформа для контент-фермы (короткие видео)

Полное техническое задание для одного агента (Claude Code, Windows), выполняющего
проект целиком — от парсинга/генерации сценариев до финального рендера видео.

---

## 0. Целевое окружение

- **ОС:** Windows 10
- **GPU:** NVIDIA GeForce GTX 1060, **6 ГБ VRAM**
- **CPU:** Intel Core i3
- **RAM:** 16 ГБ

Следствия для архитектуры:

- **TTS-инференс и видеорендер никогда не выполняются параллельно.** Оба — тяжёлые
  GPU/CPU-задачи, слабое железо (особенно i3 на препроцессинге и NVENC-очередь на GPU)
  не тянет одновременную нагрузку. Все тяжёлые операции идут через единую
  последовательную очередь задач (см. раздел 6).
- Кодирование видео — через `ffmpeg` с аппаратным энкодером **NVENC**
  (`h264_nvenc`), не через CPU-энкодер (i3 слишком слаб для реалтайм/близкого к
  реалтайм кодирования).
- Полная спецификация локального TTS (Chatterbox Multilingual, CUDA, Python 3.11,
  известные проблемы с watermarker/setuptools, расстановка ударений через `stressonnx`,
  логика `exaggeration`/`cfg_weight`/`temperature`) — вынесена в отдельный файл
  `docs/tts-stack-spec.md`. Следовать ей дословно, включая чек-лист готовности
  окружения (раздел 11 того документа) — выполнить его целиком перед началом работы
  над TTS-модулем.

## 1. Три формата контента

### 1.1. iMessage-драма
Верстается точная копия интерфейса iMessage (пузыри сообщений, анимация набора текста,
таймстемпы). По ролям разыгрывается треш-история (драма, травля, несправедливость и
т.п. — эмоционально цепляющий контент), сценарий генерируется через DeepSeek API.
Переписка озвучивается через Chatterbox по ролям, записывается в видео (скринкаст
верстки с анимацией), поверх/под неё — фоновое видео с майнкрафт-паркуром
(`shorts/parkur.mp4`, случайный отрезок нужной длины).

### 1.2. Нарезка клипов
Источник — **собственные видео правообладателя**, лежащие в локальной папке на диске
(популярные ролики/сериалы, снятые или принадлежащие пользователю). Логика нарезки —
скользящее окно: отрезки длиной **30 секунд** с шагом **2 секунды** между стартами
соседних отрезков. Пример: видео длительностью 2 минуты (120 секунд) даёт **60 файлов**
по 30 секунд каждый; отрезки, для которых 30-секундное окно выходит за конец исходного
видео (последние ~15 отрезков), будут короче 30 секунд — обрезаются по факту окончания
исходника, без паддинга. Далее к каждому отрезку добавляется озвучка и субтитры;
компоновка кадра: сверху — клип-источник, снизу — паркур.

### 1.3. Истории с форумов
Скрипт/агент парсит форумы (Reddit и аналоги), собирает посты. **Лексика без
ограничений** (любая, включая мат) — фильтрация по лексическому содержанию не
применяется; единственное ограничение — итоговая история должна укладываться по
длительности озвучки в **50–60 секунд** (см. 2.3). Отобранные и при необходимости
адаптированные под нужную длину (DeepSeek) истории озвучиваются, поверх — паркур-фон
(`shorts/parkur.mp4`), субтитры — крупные, с визуальными эффектами (word-by-word
подсветка и т.п.).

## 2. Модули системы

Единый агент реализует все модули последовательно, но архитектурно они должны быть
разделены на независимые компоненты с чёткими интерфейсами между собой — это упростит
отладку, тестирование по частям и возможное будущее подключение второго агента, если
понадобится параллелить работу позже.

1. **TTS-модуль** — обёртка над Chatterbox: инициализация модели на CUDA, очередь
   синтеза, обработка ударений через `stressonnx`, пресеты голосовой подачи (нейтральный /
   быстрый-эмоциональный / спокойный дикторский — через комбинации
   `exaggeration`/`cfg_weight`/`temperature`).
2. **Субтитры** — генерация SRT с таймкодами по готовому аудио. Рекомендация:
   `faster-whisper` (CTranslate2) вместо оригинального OpenAI Whisper — критично для
   производительности на i3.
3. **Сценарии (DeepSeek API)** — генератор диалогов для iMessage-драм (роли, реплики,
   таймкоды), рерайтер/адаптер форумных историй под формат видео-скрипта. Лимитов на
   использование API нет; единственное жёсткое требование — итоговый текст должен
   озвучиваться за **50–60 секунд** (меньше 60 секунд, но не короче 50) — при
   необходимости сокращать/дополнять историю до нужного хронометража.
4. **Парсер форумов** — сбор постов, дедупликация уже использованных историй
   (локальная БД/файл с историей обработанных ID). Фильтрация по лексике не требуется
   (любая лексика допустима); фильтр применяется только к техническим/юридическим
   ограничениям, если такие появятся (например, откровенно незаконный контент).
5. **iMessage UI-рендер** — веб-компонент (HTML/CSS/JS), запись анимации переписки в
   видео через headless-браузер (Playwright/Puppeteer) или Remotion. Полностью
   автоматизируемо по входным данным сценария, без ручной анимации.
6. **Нарезчик видео** — извлечение сегментов из исходных файлов скользящим окном
   30 секунд с шагом 2 секунды (см. 1.2), сохранение метаданных (исходный файл, таймкод
   старта/конца) для каждого сегмента.
7. **Паркур-фон** — единый исходный файл `shorts/parkur.mp4`, выбор случайного отрезка
   нужной длины через seek по таймкоду (без нарезки на отдельные файлы).
8. **Композитор** — наложение слоёв (верх/низ или UI-запись/паркур), встраивание
   субтитров с эффектами.
9. **Рендерер** — финальная сборка и кодирование через `ffmpeg` + NVENC.
10. **Оркестратор** — связывает все модули в конвейер "от сырых данных до готового
    mp4" для каждого из трёх форматов.

## 3. Формат данных сцены (внутренний контракт между модулями)

Даже при одном агенте стоит зафиксировать единый формат "сцены", которым обмениваются
модули — это упрощает отладку (можно проверить каждый модуль отдельно на моковом JSON)
и оставляет возможность параллелизации в будущем.

```json
{
  "scene_id": "uuid",
  "type": "imessage_drama | reddit_story | video_clip",
  "created_at": "ISO8601",
  "script": [
    {
      "speaker": "A | B | narrator",
      "text": "исходный текст реплики",
      "stressed_text": "текст с ударениями (U+0301)",
      "timestamp_ms": 0
    }
  ],
  "audio": {
    "path": "relative/path/to/tts_output.wav",
    "duration_ms": 0,
    "tts_params": {"exaggeration": 0.5, "cfg_weight": 0.5, "temperature": 0.8}
  },
  "subtitles": {
    "path": "relative/path/to/subs.srt",
    "format": "srt"
  },
  "background": {
    "type": "parkour_minecraft | none",
    "source_path": "relative/path/to/parkour_pool/xxx.mp4",
    "start_ms": 0
  },
  "source_video": {
    "path": "relative/path/to/original.mp4",
    "clip_start_ms": 0,
    "clip_end_ms": 30000
  },
  "output": {
    "resolution": "1080x1920",
    "path": "relative/path/to/final.mp4"
  }
}
```

`source_video` — только для типа `video_clip`; `script`/`audio` — для
`imessage_drama` и `reddit_story`. Схему рекомендуется вынести в
`schema/scene.schema.json` (JSON Schema) для автоматической валидации.

## 4. Порядок разработки (рекомендуемая последовательность)

Раз агент один, важно двигаться так, чтобы каждый этап давал проверяемый результат
до перехода к следующему, а не строить весь пайплайн "вслепую":

1. Окружение: выполнить чек-лист из `docs/tts-stack-spec.md` целиком (Python 3.11,
   venv, CUDA-версия torch, setuptools<81, stressonnx, проверка watermarker).
2. TTS-модуль отдельно: синтез тестового предложения, прослушать, подобрать базовые
   пресеты `exaggeration/cfg_weight/temperature`.
3. Субтитры отдельно: прогнать TTS-аудио через `faster-whisper`, проверить точность
   таймкодов на кириллице.
4. Нарезчик видео + подключение паркур-фона (`shorts/parkur.mp4`): чисто механическая
   часть, не зависящая от TTS — можно делать параллельно с п.2–3.
5. Композитор + рендерер (ffmpeg/NVENC): собрать один тестовый ролик вручную из готовых
   аудио+видео+сабов, проверить производительность на целевом железе.
6. DeepSeek-интеграция: генерация сценария для одного формата (начать с историй с
   форумов — там нет UI-компонента).
7. Оркестратор для формата "истории с форумов" целиком — первый end-to-end тест.
8. iMessage UI-рендер — самый трудоёмкий визуальный компонент, делать после того как
   остальной конвейер обкатан на более простом формате.
9. Оркестратор для оставшихся двух форматов.
10. Парсер форумов + фильтрация — можно подключить в любой момент после п.6, не
    блокирует остальную разработку (пока использовать вручную подготовленные истории).


## 6. Очередь задач

- Простая очередь на файловой системе или SQLite — без внешних зависимостей
  (Redis и т.п. не нужны для одиночного агента на этом железе).
- Джобы: `tts_synthesis`, `subtitle_generation`, `video_render`, `video_clip_extraction`.
  Выполняются **строго последовательно**, не параллельно.
- Каждый модуль должен уметь тестироваться на моковых данных из `/mock-data`, не
  дожидаясь готовности остальных модулей — это позволяет проверять части конвейера
  изолированно, даже работая в одиночку.

## 7. Git

- `main` — стабильная ветка, рабочие изменения — через отдельные ветки по фиче
  (`feature/tts-module`, `feature/imessage-ui` и т.д.) с PR в `main` (даже соло-разработка
  выигрывает от истории ревью и отката).
- `.gitattributes`: `* text=auto` — нормализация переносов строк.
- `.gitignore`: `venv/`, `__pycache__/`, `*.pyc`, локальные конфиги, содержимое
  `/data/source-videos` и `/shorts/parkur.mp4` (тяжёлые медиафайлы — не в git, отдельное
  хранилище/облако при необходимости).

## 8. Параметры проекта (зафиксировано)

- **VRAM:** GTX 1060, 6 ГБ.
- **Нарезка исходных видео:** окно 30 секунд, шаг 2 секунды между стартами
  (2-минутное видео → 60 файлов, из них последние ~15 короче 30 секунд).
- **Паркур-фон:** единый файл `shorts/parkur.mp4`, случайный seek под нужную длину.
- **Фильтрация форумных постов:** без ограничений по лексике.
- **DeepSeek API:** без лимитов по использованию; итоговый сценарий озвучивается за
  50–60 секунд.
