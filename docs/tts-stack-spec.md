# Технический стек: синтез русской речи на Chatterbox Multilingual TTS

Полное описание рабочего стека, окружения и известных подводных камней — для использования как технического задания.

## 1. Целевое окружение развёртывания

- **ОС:** Windows 10
- **GPU:** NVIDIA GeForce GTX 1060 (CUDA, compute capability 6.1)
- **CPU:** Intel Core i3
- **RAM:** 16 ГБ

Важные следствия для стека:

- Инференс должен идти на **CUDA**, а не на CPU — с GTX 1060 разница в скорости синтеза кратная. Слабый i3 делает CPU-инференс практически неприемлемым по времени.
- GTX 1060 обычно выпускается в вариантах 3 ГБ / 6 ГБ VRAM — перед установкой уточнить конкретный объём. Chatterbox Multilingual + PyTorch на CUDA должны уместиться в 6 ГБ VRAM с запасом; на 3 ГБ возможны проблемы с памятью на длинных текстах — тогда синтезировать по предложениям, а не абзацами целиком.
- 16 ГБ RAM достаточно для самой модели, но при параллельной работе с другими тяжёлыми приложениями (браузер, монтаж видео) может не хватать — держать генерацию TTS как отдельный процесс/скрипт, не встраивать в тяжёлый основной пайплайн монтажа напрямую.
- Intel i3 — слабый CPU для препроцессинга (токенизация, `stressonnx`, `librosa`, если используется). На больших текстовых батчах препроцессинг может стать узким местом наравне с самим инференсом — учитывать при проектировании очереди задач.

## 4. Устройство инференса (CUDA)

На Windows с GTX 1060 нужен PyTorch, собранный под CUDA (не CPU-only сборка по умолчанию с PyPI):

```powershell
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu121
```

(Версию CUDA-билда — `cu121`/`cu118`/др. — сверять с актуально поддерживаемыми PyTorch и установленной версией драйвера NVIDIA на момент установки.)

Определение устройства в коде:

```python
device = "cuda" if torch.cuda.is_available() else "cpu"
```

Если `torch.cuda.is_available()` возвращает `False` — значит либо стоит CPU-only сборка torch, либо не установлены/устарели драйверы NVIDIA — проверять в первую очередь это, а не переустанавливать Chatterbox.

## 6. Известная проблема: конфликт имени файла

Тестовый/рабочий скрипт **нельзя называть `chatterbox.py`** — если внутри есть `import chatterbox`, Python найдёт локальный файл вместо установленного пакета и упадёт с `'chatterbox' is not a package`. Использовать любое другое имя (например `chatterbox_run.py`, `tts_pipeline.py`).

## 7. Известная проблема: watermarker (Perth) и setuptools

Chatterbox использует `resemble-perth` для встроенного водяного знака в аудио. `resemble-perth==1.0.1` зависит от старого `pkg_resources`, который новые версии `setuptools` (например 84.x) больше не поддерживают в нужном виде.

Симптом маскируется try/except внутри Perth — снаружи это выглядит так:
```
TypeError: 'NoneType' object is not callable
```
или, после наивного monkey-patch заглушки:
```
AttributeError: 'NoneType' object has no attribute 'apply_watermark'
```

**Фикс:**
```powershell
python -m pip install "setuptools<81"
```
Проверка, что watermarker реально восстановился:
```powershell
python -c "import perth; print(perth.PerthImplicitWatermarker)"
```
Должен вывести реальный класс, а не `None`. Предупреждение `pkg_resources is deprecated as an API` при этом останется — это ожидаемо, не ошибка.

Если ранее делался временный monkey-patch/заглушка для `PerthImplicitWatermarker` — его нужно убрать полностью после фикса setuptools, иначе `None` может "прилипнуть" к состоянию модуля/скрипта и генерация продолжит падать даже при формально исправленном Perth.

## 8. Расстановка ударений

- У Chatterbox есть встроенный хук на автоматическую расстановку ударений для `language_id="ru"` — вызывается пакет `russian_text_stresser` (внутри `chatterbox/models/tokenizers/tokenizer.py`, функция `add_russian_stress`).
- Если `russian_text_stresser` не установлен, ударятор **тихо отключается** (лог `russian_text_stresser not available - Russian stress labeling skipped`), и текст уходит в модель без изменений — без ошибки, просто без ударений.
- `russian_text_stresser` тянет `spacy==3.6.x` и потенциально конфликтует с остальным окружением, поэтому вместо него используется независимый пакет **`stressonnx`** (чистый onnxruntime + numpy, без torch/spacy), который расставляет ударения в **том же формате**, что и родной ударятор Chatterbox: комбинирующий акут (Unicode U+0301) над ударной гласной, с учётом контекста (за́мок/замо́к, ко́мпас/компа́с и т.п.).

```python
from stressonnx import stress
stressed_text = stress(raw_text, "ru")
```

**Важно:** формат ударения (комбинирующий акут) подтверждённо работает и озвучивается корректно моделью — проверено на полноценных предложениях. На **одиночных коротких словах** (1 слово) наблюдается нестабильность генерации (повтор слова или "бормотание") независимо от наличия ударения — это известный краевой случай авторегрессивной модели на слишком коротких входах, тестировать нужно на полных предложениях.

## 9. Логика регулировки темпа и манеры речи

У `model.generate()` **нет** прямого параметра `speed`. Темп и характер подачи регулируются косвенно через три параметра сэмплирования, и они взаимозависимы:

- **`exaggeration`** (по умолчанию 0.5) — сила эмоциональной выразительности. Это главный рычаг темпа: чем выше значение, тем интенсивнее и одновременно **быстрее** речь; чем ниже — тем спокойнее и медленнее.
- **`cfg_weight`** (по умолчанию 0.5) — насколько жёстко модель держится референсного голоса/паттерна речи. Работает как компенсатор: если после повышения `exaggeration` темп стал слишком быстрым, понижение `cfg_weight` (~0.3) "притормаживает" и делает подачу более размеренной, не убирая экспрессию.
- **`temperature`** (по умолчанию 0.8) — вариативность сэмплирования при выборе следующего токена. На темп влияет слабее, чем первые два, но ниже значение (~0.6–0.7) даёт более стабильный, предсказуемый ритм без случайных ускорений/пауз; выше — больше живой случайности, но и риск нестабильности.

Логика подбора:

| Хотите | Что крутить |
|---|---|
| Медленнее, спокойнее, дикторская подача | `exaggeration` ↓ (0.2–0.35) + `cfg_weight` ↓ (0.3–0.4) |
| Быстрее, живее, эмоциональнее | `exaggeration` ↑ (0.6–0.8), `cfg_weight` можно оставить 0.5 |
| Нейтрально, "по умолчанию" | `exaggeration=0.5`, `cfg_weight=0.5` (дефолт) |
| Стабильнее, меньше рывков в паузах | `temperature` ↓ (0.6–0.7) |

Правильный порядок подбора — эмпирический, не формула: сгенерировать одно и то же предложение с несколькими комбинациями параметров, сравнить на слух, и уже от ближайшего варианта подстраивать `cfg_weight`/`temperature` шагом ±0.05–0.1.

**Постобработка (`librosa.effects.time_stretch`) не рекомендуется как основной способ регулировки скорости** — даёт артефакты фазового вокодера (металлический призвук на растяжении). Допустима только как тонкая докрутка (не более ±5–10%) поверх уже подобранных параметров генерации, когда нужная скорость лежит "между" тем, что дают комбинации `exaggeration`/`cfg_weight`.

## 10. Итоговый пайплайн

```
сырой русский текст
      ↓
stressonnx.stress(text, "ru")   → текст с ударениями (U+0301)
      ↓
model.generate(
    stressed_text,
    language_id="ru",
    exaggeration=<подобрано под нужный темп/манеру>,
    cfg_weight=<компенсация темпа>,
    temperature=<стабильность>,
)
      ↓
torchaudio.save(...)            → WAV на выходе
      ↓
(опционально) librosa time_stretch в пределах ±5–10% как финальная докрутка
```
